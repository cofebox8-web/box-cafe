## 🔴 لماذا ليس 100% — نواقص وفجوات فعلية موجودة الآن

### 1. ترحيل إصلاح ترقيم الطلبات غير مرفوع بعد
الترحيل `202609280019_global_order_codes.sql` (يحوّل توليد رقم الطلب من `MAX()+1` غير الآمن تزامنياً إلى `sequence` ذرية آمنة) **موجود كملف محلي غير محفوظ بـ git بعد (`git status` يُظهره `??`)**. لا أقدر أتحقق هل طُبِّق فعلاً على قاعدة الإنتاج عبر SQL Editor بشكل منفصل أم لا. **إن لم يُطبَّق بعد، يبقى احتمال حقيقي (وإن كان نادراً) أن يفشل طلبان متزامنان بنفس الثانية برقم طلب مكرر.** يجب تأكيد رفعه وتطبيقه على Supabase قبل اعتبار نظام الطلبات آمناً بالكامل تحت الضغط.

### 2. لم يُختبَر أي شيء حياً بحساب حقيقي من طرفي أنا
كل ما أعلاه تحقّق عبر قراءة كود واستعلامات مباشرة بمفتاح anon العام — **لم أسجّل دخولاً حقيقياً كويتر أو مطبخ أو أدمن على الموقع المنشور لأني لا أملك ولا يجب أن أطلب بيانات دخولكم الحقيقية.** يعني: لم يتأكد أحد (غيرك أنت شخصياً) أن دورة الحياة الكاملة (ويتر يرسل طلباً حقيقياً → يصل مطبخ حقيقي → يتغير حالته → يصل تنبيه للويتر فعلياً على جهاز حقيقي) تعمل من ألفها لياءها في ظروف استخدام حقيقية. **هذا الاختبار الحي يبقى مسؤوليتك أنت قبل أي إطلاق فعلي للعملاء.**

### 3. قرارات عمل أساسية لا تزال مفتوحة رسمياً (موثّقة في `docs/architecture.md`)
- **طريقة الدفع غير مطبَّقة إطلاقاً** — لا عمود لوسيلة الدفع بجدول `orders` حتى الآن. أي تقرير مبيعات حالي هو إجمالي قيم الطلبات فقط، وليس تقرير تحصيل نقدي/بطاقة حقيقياً.
- من يضغط "تم التسليم" (الويتر أم المطبخ) لا يزال قراراً غير محسوم بالكود.
- قواعد الخيارات الإلزامية وحدودها لكل منتج تُدخل يدوياً لكل منتج، ولا توجد قاعدة عامة معتمدة.
- هوية العلامة النهائية (الشعار الفعلي، الألوان النهائية) لم تُعتمد بشكل قاطع.

### 4. بقايا تنظيف بسيطة لم تُنفَّذ (لا تُسبب أعطالاً، لكنها مخاطرة صيانة مستقبلية)
- ملف `public/js/supabase-scoped-client.js` ودالة `createScopedSupabaseClient` بـ`supabase-client.js` ما زالا موجودين رغم أن لا شيء يستوردهما بعد تبسيط نظام الدخول — كود ميت، يزيد احتمال ارتباك أي تعديل مستقبلي.
- ملف `public/js/roadside-app.js` كود ميت بالكامل، لا تحمّله أي صفحة.

### لم يُتحقق/يُنفّذ على الإنتاج

- لم يمكن استخدام Supabase CLI لأنه غير متاح في بيئة العمل، ولم يُستخدم `npx` أو تثبيت أدوات جديدة.
- لوحة Supabase المفتوحة تعرض مشروعاً مختلف المعرّف عن المشروع المحدد في إعداد الموقع، كما أن المشروع الظاهر باسم `box-cafe` حالته متوقفة. لذلك لم يُشغّل أي SQL على تلك اللوحة ولم يُفترض أن الترحيل 019 مطبّق.
- تعذّر تأكيد وجود `public.order_code_seq` أو مقارنتها بأرقام الطلبات في قاعدة الإنتاج الصحيحة.
- لم تُنشأ طلبات اختبار حقيقية؛ لم تتوفر جلسة مطبخ منفصلة موثوقة لإكمال الدورة وتنظيف أثر الاختبار. نتيجةً لذلك لا يوجد تحقق حي جديد للظهور اللحظي أو تنبيه الويتر أو تزامن رقمَي طلب.
- ملف `supabase/migrations/202609280019_global_order_codes.sql` ما زال غير متتبع في Git، ولم يُضمّن أو يُثبّت قبل التحقق من تطبيقه على قاعدة الإنتاج الصحيحة.

## تحديث تحقّق مستقل — 2026-09-29 (بعد المتابعة أعلاه)

المنفّذ أعلاه كان محقّاً بعدم التخمين — لوحة Supabase التي فتحها فعلاً كانت
تعرض مشروعاً آخر متوقفاً (`box-cafe`)، والحذر بعدم تنفيذ أي SQL هناك كان
القرار الصحيح. لكن بيئة عمل أخرى متاحة لي فيها Supabase CLI **مرتبط فعلاً
وبشكل صحيح** بالمشروع الحقيقي (`rtzzoyaxivujzvghudgz`، يطابق `config.js`
تماماً)، فتحققت مباشرة عبر `supabase db query --linked` (قراءة فقط،
عبر Management API، بلا كلمة مرور قاعدة بيانات):

```
select relname from pg_class where relkind='S' and relname='order_code_seq';
→ موجود فعلاً

select last_value, is_called from public.order_code_seq;
→ last_value=103, is_called=true

select prosrc from pg_proc where proname='place_customer_order';
→ المصدر الفعلي المُنفَّذ على الإنتاج مطابق حرفياً لنسخة migration 019
  (وليس النسخة القديمة MAX()+1)

select count(*), min(order_code), max(order_code) from public.orders
where order_code ~ '^B-[0-9]+$';
→ 3 طلبات: B-101, B-102, B-103 — متسلسلة بلا فجوة ولا تكرار
```

**الخلاصة: migration 019 مُطبَّق فعلاً ويعمل بشكل صحيح على قاعدة
الإنتاج الحقيقية.** البند الحرج رقم 1 بالقسم أعلاه **أُغلق فعلياً على
مستوى قاعدة البيانات**؛ المتبقي فقط هو إضافة ملف الترحيل نفسه لـgit
حتى يطابق المستودع الواقع الفعلي (لا يغيّر شيئاً حياً، توثيق فقط).

الاختبار الحي الكامل لدورة الطلب (ويتر → مطبخ → تنبيه) **يبقى غير
منفَّذ بحساب حقيقي** كما هو موثَّق بالبند 2 أعلاه — هذا لم يتغيّر.
